# 編集部ノート（editor-notes）

タグLP（`/tag/{名前}`）の冒頭に置く「◯◯は海外でどう見られているか」の編集部要約。
**`data/editor-notes.json` が唯一の正**（型は `src/lib/editorNotes.ts`）。キーは
選手・ファイター＝カタログの slug、チーム＝`src/lib/teams.ts` の slug。

声ピックアップが**生のコメント**を見せるのに対し、ノートは**それを横断した傾向の言語化**＝
「◯◯ 海外の反応」で来た読者が30秒で全体像を掴む独自テキスト。ここが薄いとLPは
記事フィードだけの自動生成面になる。

> ⚠️ ノートは現在形（いま海外はこう見ている）で書くのに、書き直しが「思い出したときだけ」
> だったため、2026-08-19 の点検で 16球団がノート不在・14球団が6〜8日静止していた。
> 検出器（`editor-note-candidates.mjs`）と週2回の日課はその対策。

## 手順

### 1. 鮮度を見る

```bash
node scripts/editor-note-candidates.mjs          # 30球団の鮮度ギャップ表（書き直し優先順）
```

優先度は「ノート不在 ＞ ノート以降に増えた記事の本数 ＞ 経過日数」。
**1回の更新で上から6〜8球団**を目安にする（全部やると1本ずつが雑になる）。

### 2. 素材を読む

```bash
node scripts/editor-note-candidates.mjs --team whitesox,cubs --days 30
node scripts/editor-note-candidates.mjs --stale 6 --material   # 上位6球団まとめて
```

出力は**記事JSONの実在コメントの機械コピー**（人も AI も文言を触らない）。2部構成:

- チームタグの付いた記事の上位コメント（日次記事は既定で除外＝コメント欄が他球団の話で埋まるため）
- **他記事での言及**＝チーム名を含む発言。専用記事が途切れている期間はここが主材料になる

### 3. 書く

- **300〜400字**。地の文は編集部の言葉、`「」` は**引用専用**（強調に使わない）
- 引用は素材からの**逐語コピー**。要約・言い換えをして `「」` に入れない
- 構成の型: ①いまの見え方を一文で ②それを裏づける代表的な声2〜3本 ③留保・弱点として
  繰り返される声 ④日本人選手がいれば現地での扱われ方（言及が少ないならそう書く）
- 前回のノートは全部捨てない。**変わっていない芯は残し、動いた部分を差し替える**
  （例: 7月の失速→8月の反転、補強の評価、看板選手の入れ替わり）
- 禁止: 推測・捏造、「ニキ」表現、`「」` の入れ子、絵文字だけの引用

### 4. 保存して照合する

`data/editor-notes.json` に `noteJa` と `updatedAt`（YYYY-MM-DD・JST）で保存し、**必ず**:

```bash
node scripts/check-editor-notes.mjs   # 「」の中身を全記事のコメントと逐語照合
npm run build:gate                    # 通ったときだけ公開する
```

素材が動いていない主題は**書き直さない**（`updatedAt` だけ進めるのは偽の鮮度シグナル）。

### 5. 公開

`origin/main` から作業ブランチを切って編集し、`git push origin <branch>:main`
（本店は `gh pr create` 不可）。ローカルは数百コミット遅れることがあるので、
記事を数える作業は必ず fetch 後の origin/main 基準で。
