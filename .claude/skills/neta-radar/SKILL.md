# ネタ発見レーダー（neta-radar）

ネタの**発見**を担うスキル。自動化済みのネタ発生源が「日本人選手の出場試合（jp-games）」1種類しか
なく、それ以外（Reddit の盛り上がりスレ・YouTube でバズった動画・トレード/乱闘/珍プレー・興行）が
村山の人力発見に 100% 依存している構造欠陥を、既存スクリプトの配線だけで埋める。

> 編集ルール（R1〜R13）・狙う検索クエリ5クラス表・比重の値は **matome スキルが唯一の正**。
> 日本人選手の試合の網羅は **jp-games が正**（このスキルは重複して拾わない・参照だけする）。
> このスキルは「候補を出して選ばせる」まで＝**記事化・保存はしない**。

## 原則
- **「面白いネタを探す」ではなく「枯れているクエリクラスに燃料を入れる」**。勝ち筋は LP＝記事は
  LP への燃料（matome の5クラス表が正）。
- **候補ゼロの日はゼロと言う**（埋め草候補で数を水増ししない。DM疲れ＝レーダー死の最大要因）。
- **提示は全競技合わせて最大5件＋推奨1件**。比重（MLB 7 : ボクシング 2.5 : MMA 0.5）を超える
  増産提案をしない（ボクシングは興行前後のみ・MMA は月2〜4本目安。jp-games の日本人試合は枠外）。

## Step 0 — 燃料ゲージ（クラス別の在庫と鮮度）
> ⚠️ **集計の前に必ず `git fetch origin main` して `origin/main` を基準にする**（2026-07-18 事故）。この repo は
> 複数の Claude セッション＋毎日16時のクラウド jp-games ルーティンが並行で書くので、ローカル作業ツリーは
> 平気で数百コミット遅れる。遅れた木で数えると **①在庫を過少に見て枯れ判定を誤り ②既存記事を見落として
> 重複記事を作り ③回収済みの興行を「回収漏れ」と誤報する**（実際に3つとも同時に起きた）。
> 数え方は `git ls-tree -r --name-only origin/main data/threads/` か、`git worktree add <tmp> origin/main` した
> クリーンな木で ls/grep する。同じ理由で **Step 1-B の既記事化チェック（videoId の grep）も origin/main 基準**で走らせる。

`data/threads/` を ls / grep で集計する（コード新設不要）:
- 競技別の直近7日の本数・最終記事日
- チームタグ出現数（`grep -l '"カブス"' data/threads/mlb/*.json | wc -l` 方式）→ 3件未満＝
  チームLP未達（`TEAM_HUB_MIN_ARTICLES`・`src/lib/teamHub.ts`）のチーム一覧
- 枯れ判定の目安: ③MLB＝今日まだ0本（毎日1本が下限）／④ボクシング＝最終記事から10日超／
  ⑤MMA＝14日超／②＝LP未達チームに未記事化の試合がある

## Step 1 — 供給源スキャン（5系統）
### A.【参照のみ】日本人選手の試合
`node scripts/fetch-mlb-stats.mjs games --json` の `existingArticle: null` は **jp-games の領分**＝
候補表には「jp-games へ」とだけ書く（ここで動画同定・記事化まで踏み込まない）。

### B.【自動】YouTube 定点監視（主力）
`references/channels.md` の監視台帳を上から順に:
```sh
node scripts/fetch-youtube.mjs latest <channelId> 10
```
- **足切り**: 公開48h以内 かつ（commentCount が同チャンネル直近10本の中央値の2倍以上、または
  viewCount 上位2本）。ハイライト定常枠（jp-games が拾う分）は除外。
- `search` は使わない（quota が latest の約100倍。チャンネル特定できない時の補助のみ）。
- 拾った videoId は `grep -rl "<videoId>" data/threads/` で既記事化を除外（二重ガード）。
- 生の取得 JSON は `_local/queue/` に置き**コミットしない**（YouTube API 規約）。

### C.【半自動】興行カレンダー（ボクシング/UFC）
`references/events.md`（近日興行の台帳）を見て、興行日が72h以内なら **D型3本セット**
（前日予想・直後実況・翌日反応＝matome R12-D）のどのタイミングかを判定して候補に載せる。
台帳が空・古いときは WebSearch で当月の興行（井上尚弥・UFC ナンバー・朝倉海/平良達郎の参戦）を
確認して追記してから使う。

### D.【半自動】Reddit 深掘りスキャン（公開RSS ＋ old.reddit HTML）
公式 API は承認待ちだが、**公開RSS と old.reddit の HTML は通る**＝手動貼り付けを待たずに掘れる
（`.json` は常に403）。**狙うのは単独の名言でなく、海外ファン同士の2〜4レスの掛け合い**。
手順の正は **`references/reddit-scan.md`**（ルート実測 → 球団板を選ぶ → 月間トップを選手名で引く →
コメントRSSは深さ優先＝連番が返信チェーン → 当たりスレの型8種 → 濾す → 渡す）。要点だけ:

- ⭐**コアな会話は r/baseball でなく球団板にある**。ゲームスレは捨て、感想・考察・内輪スレだけ拾う
- ⭐**日本語圏で既に流通しているネタは捨てる**（面白さとは別の一次フィルタ）
- ⭐**板の数字は statsapi で当て直す**（ファンの神話化が混ざる）
- ▲スコアが取れない日がある＝その日は**票数を本文に書かない**

スクリプトは `_local/reddit-scan/`。巡回先の定番 URL は `references/channels.md` 末尾の Reddit 欄。

### E.【自動】MLB の移籍・契約（オフシーズンの主力）
```sh
node scripts/fetch-transactions.mjs            # 直近7日（ET）
node scripts/fetch-transactions.mjs 2026-12-01..2026-12-15   # ウィンターミーティング等
```
11月〜2月中旬はMLBの試合が無く A・B が枯れるが、**検索需要は止まらない**＝オフは
「FA宣言（11月上旬）→ ウィンターミーティング（12月）→ 契約・入団会見（1月）」の季節で、
日本人選手や大物が動くたびに「◯◯ 移籍 海外の反応」が跳ねる。試合ハイライト系より競合も薄い。

- **★★★（日本人）は最優先**＝移籍先チームのファンがどう受け止めたかが、そのままこのサイトの型
- ★★ は今季成績が大物水準の選手（打席250以上・IP80以上のサンプル下限つき）
- `※記事あり(日付)` が付いた選手は**もう書いている**＝重複記事を作らない
- 末尾の「⚠️ カタカナ未収録」は、**記事を書く前に** `data/player-names-ja.json` へ足す
  （オフの主役は外国人選手＝ここを放置すると記事に英語名がそのまま出る）
- 反応そのもの（現地ファンの声）はこのスクリプトからは取れない＝D（Reddit 巡回注文）と
  B（YouTube・MLB Network 系の移籍解説）に繋いで素材を集める

## Step 2 — 候補チケットにして格付け
- 優先度: **枯れているクラスの燃料 ＞ 試合直後24h以内の感情ネタ ＞ view/comment の実測熱量**。
- 1候補 = 1チケット。matome / jp-games は値を再計算せずそのまま使う:
  ```
  { sport, kind: "youtube" | "reddit-manual" | "event",
    sourceUrl, videoId, suggestedId: "{YYYY-MM-DD(JST)}-{英語スラッグ}",
    狙いクエリ: "①〜⑤クラス＋具体KW（例: ②「カブス 海外の反応」）",
    tags案: matome R11 の基礎セット, タイトル案: matome R8 の型（言い切り型/引用フック型）で仮置き,
    検出理由: view/comment の実測値 or 興行タイミング, 委譲先: matome | jp-games | Reddit注文 }
  ```

## Step 3 — 候補ボード（出力）
上位5件＋**推奨1件（理由1行）**の表をチャット1枚（クラウド実行時は Slack DM 1通）で提示:
`候補 / ソース / 狙いクエリ / タイトル案 / 委譲先 / 一言理由`。村山が選んだら該当スキルへ委譲して終了。

## クラウド相乗りモード（radar-only）
毎日16:00 の jp-games ルーティンの**末尾**に足す場合は radar-only＝候補ボードを Slack DM に載せる
**だけ**（コメント取得・記事化はしない）。失敗しても jp-games の成果に影響させない（ベストエフォート・
末尾実行）。不安定なら schedule スキルで別トリガーに分離する。

## 必ず守ること
- **捏造しない**: 存在しない動画・スレ・興行を候補にしない。数値（view/comment）は実測のみ。
- **チャンネル ID は必ず実測で台帳に足す**（`fetch-youtube.mjs search "<チャンネル名>" 3` で確認して
  から。推測で書かない。初回セットアップは村山同席で）。
- 未承認の Reddit API・`.json` を叩かない／**他社リーダーの UA を騙らない**（自己申告 UA で公開RSSと
  old.reddit HTML だけ使う＝BAN根拠を作らない。公式 API 承認後に Step 1-D を全自動化する）。
- 「MMA 海外の反応」をターゲット語にしない（SERP 汚染＝matome 5クラス表の注記が正）。
