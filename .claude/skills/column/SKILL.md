# 長文コラム作成スキル（中の人ボイスの読み物版）

目的：**X で読者を掴んでいる「中の人」の人格を、サイトの長文に移植する**。
検索で勝つためではない。週100万インプの X からプロフ経由で来た読者に
「この人の書くものは追いかけたい・このサイトはブックマークしておきたい」と思わせる
＝フォローと再訪の理由を作るのがコラムの仕事。**評価軸は表示回数でなく滞在・回遊・再訪**。

> 位置づけ：試合の反応まとめ（matome / jp-games）＝flow は毎日自動で積む。
> コラム＝そのflow資産を束ねて意味を与える stock。週1本・少数精鋭。量産しない。

## 声の正典は x-post（ここに複製しない）

**書き始める前に必ず `.claude/skills/x-post/SKILL.md` と同 `references/feedback-log.md` を読む。**
キャラクター設定（寝不足MLBオタク・一人称は俺）・脱AIルール・体温の作り方は全てあちらが唯一の正。
本スキルはその声を**2,000字で維持するための追加規律だけ**を定める。

### 長文でも変わらないもの（x-post から継承）
- 主役は俺の感情。海外の声もデータも、俺が反応する対象。
- 地の文にカギカッコ・引用符・半角スペースを使わない。まとめダッシュ禁止。
- データは宣言せず感情に溶かす。同じ論点の数字は一番効く1個だけ。
- 日本人選手は苦しい数字でも長い目で立てる。締めは上向きか余韻。
- 煽り語・絵文字連打・記号芸なし。叫ばない。

### 長文だけの追加ルール（140字と違うところ）
1. **引用は quote ブロックで出せる**（X の"また聞き"縛りの緩和）。ただし：
   - 引用文は既存スレ JSON の `bodyJa` を**一字も変えず**使う（切り貼り・要約・捏造禁止）。
   - `cite` に出どころ＋実測いいね数を書く（例: MLB公式ハイライトのコメント欄・いいね447）。
   - 1本のコラムで quote は**2〜3個まで**。残りの声は地の文に"また聞き"で溶かす（全部引用にすると
     ただのまとめに戻る＝コラムの負け）。
2. **章立ての見出しも俺の声**で書く。説明見出し（〜について／〜の分析）は失格。
   言いさし・体言止め・ツッコミが見出しになっていい。
3. **章ごとに俺の感情の段落を最低1つ**。事実→事実→事実と並べた章は無機質＝失格。
4. **尺は1,500〜2,500字**（読了5分以内）。長いほど偉いは嘘。削って濃くする。
5. **1本に太い題材は2〜3個まで**。今週の全部を書かない。刺さったものだけ。
6. **文体の圧を6〜7割に落とす**。140字の一撃は毎行がフックだが、長文で全行フックだと読み疲れる。
   フックは章の頭と締めに置き、間は少し温度を下げた語りで流す。

## 型（3つ。まず①を定番化する）

| 型 | 中身 | 頻度 |
| --- | --- | --- |
| ①週刊総括 | 今週のMLB、俺が刺さったやつ。スレ資産2〜3本＋成績データを束ねる | 週1（固定） |
| ②論争深掘り | 1テーマ（契約論争・ABS・起用法等）を関連スレ複数で立体化 | ネタが立った時 |
| ③選手ストーリー | 日本人選手1人の物語。選手ハブと相互に厚くする | 節目の時 |

## 材料ルール（捏造ゼロの担保）

- 海外の声：**自サイトの `data/threads/` に既にある `bodyJa` だけ**。新規取得は matome の仕事。
- 成績データ：`data/jp-players-stats.json`（snapshot）と各スレの `stats`/`summaryJa` の数値だけ。
  順位・記録などスレ外の文脈ファクトを足すときは**出す前に必ず裏取り**（standings.json 等）。
- **スレの棚卸しは origin/main 基準**（ローカル作業ツリーは数百コミット遅れることがある。
  正はメモリ `stale-local-branch-poisons-radar`）。
- 束ねたスレ記事の主役タグを `tags` に入れる＝記事末尾の関連記事（RelatedArticles）で
  flow⇔stock の内部回遊が自動配線される。

## 出力フォーマット

`data/columns/{id}.json`（型は `src/types/column.ts` の `Column`）。要点：

- `id`: `YYYY-MM-DD-` プレフィックス＋kebab-case。`kind`: `"column"`。`sport`: 主競技。
- `title`: ja は俺の声のタイトル（検索最適化しない）。en は素直な英訳でよい。
- `lead`: 導入2〜3文。今週の体感から入る。
- `heroQuote`: いちばん美味い実在コメントをフックに掲げる（任意だが週刊総括では推奨）。
- `blocks`: `heading` / `paragraph` / `quote` の並び。`video` は原則使わない（動画はまとめ記事の領分）。
- `publishedAt`: JST。新着フィードは日付降順なので、トップに出したければ既存最新より新しく打つ
  （正はメモリ `newest-fetchedat-feed-gotcha`）。
- `source` / `sourceUrl`: 自前コラムなので**書かない**（インタビュー翻訳記事だけの項目）。
- `thumbUrl`: 固有サムネ。**週刊総括は手描きプレート図版を毎号生成する**：
  `node scripts/column-thumb.mjs <columnId> --vol <号数> --date <YYYY.M.D>`
  → `public/media/{columnId}-og.jpg`（1280×720）が出るので `thumbUrl` に `/media/{columnId}-og.jpg`。
  テイスト（紙白×墨線画×赤は縫い目一点×縦組み和文）は3号店のプレート図版の移植＝スクリプトが正。
  縦組みは同梱フォント クレー One SemiBold（`scripts/assets/`・OFL・2026-07-23村山採用）＝
  手描きボールと筆致を揃えるための選定。フォント変更はスクリプト側を直す。

## 手順

- **Step 0**: x-post の SKILL.md＋feedback-log、本スキルの `references/feedback-log.md` を読む。
- **Step 1**: 素材の棚卸し（origin/main 基準）。今週のスレから太い題材2〜3個と、使う実在コメント
  （score つき）を抜き出す。数字は snapshot/standings で裏取り。
- **Step 2**: 構成を先に組む（lead→章2〜4→締め）。章見出しを俺の声で仮置きしてから本文。
- **Step 3**: 執筆。x-post の脱AIルールを地の文に通す。quote は bodyJa 原文ママ。
- **Step 4**: 自己採点（下記）。落ちたら書き直す。
- **Step 5**: JSON 化して保存。ローカル build で表示確認（コラムは SSG＝型エラーは build で割れる）。
- **Step 6**: 公開後、一番いい一段落を素材に **x-post へ予告編ポストを委譲**（本文リンク無し・
  プロフ導線が正。送客の段取りは x-share）。新しい学びは feedback-log に追記。

## 出す前の自己採点（不合格なら作り直す）

- □ x-post の自己採点を地の文が全部通るか（カギカッコ／半角スペース／まとめダッシュ／宣言ゼロ）
- □ 章見出しが俺の声か（説明見出しになっていないか）
- □ 各章に俺の感情の段落があるか（事実の羅列章がないか）
- □ quote は2〜3個以内・全て実在の bodyJa 原文ママ・cite にいいね数があるか
- □ 数字は1論点1個・裏取り済みか
- □ 1,500〜2,500字に収まっているか
- □ 締めが上向きか余韻か（説明で終わっていないか）
- □ 読み終わった人が、この人の来週も読みたいと思うか

> 運用メモ：まず週刊総括を4本（4週）回し、GA4 の滞在・回遊・プロフ経由再訪で継続判断する。
> 判定前に頻度を上げない（試合まとめで量≠需要は実証済み）。
