# きょうの日本人選手（jp-daily）

その日(ET)に出場した**日本人選手だけ**を、

1. **カード**（1080×1350・X にリンク無しで単体投稿する拡散の本体）
2. **日次記事**（サイトに置く読み物。`Thread.daily` のコーナー構成）

の2点セットにする日次シリーズ。毎日 16:00 JST のクラウドルーチンが自動で回す。

記事は**帯番組のコーナー構成**（骨子v2・2026-07-30 確定）:

```
① きょうの3行 → ② きょうの主役 → ③ 残り全員ひと言ずつ
→ ④ きょうの現地ざわつき → ⑤ きょうの1枚 → ⑥ あすの日本人
```

v1（試合ごとのスコア表→成績→コメント列の反復）は「データベースの出力」でボツになった。
読み物にするのは**②の書き方＝編集部が試合を地の文で語り、現地コメントを証言として差し込む**こと。

> 記事の中身（翻訳・タグ・禁止事項）は **matome スキルが唯一の正**。ここにはシリーズ固有の型だけを書く。

> **📅 日付規約**（jp-games と同じ）
> - スクリプトの引数 ＝ **ET（現地の試合日）**
> - **サイトに出す日付・記事 id は JST**（ET の翌日）。カードの見出しも JST。
> - 動画同定にだけ ET を使う（`titleDateName` ＝ "July 29"）。

---

## なぜ1日1本に集約するのか

日本人が絡む試合を1試合1記事で出すと、同じ日の記事どうしがタイトルも内容も似て**互いを食う**
（薄い試合記事は 2026-07 に 39 本が noindex 入りした）。1日1本の濃い日次記事に寄せて、
個別記事は**ライバル（非日本人）だけが出た試合**に限る。

## Step 1 — その日の日本人を取る

```sh
node scripts/fetch-mlb-stats.mjs jpday             # 既定＝ET昨日
node scripts/fetch-mlb-stats.mjs jpday 2026-07-29  # 日付指定（ET）
```

| キー | 中身 |
| --- | --- |
| `date` / `day` | ET の試合日 / 開幕からの通し番号（カード＆記事の `No.127`） |
| `players[].name` `team` `today` `note` | 名前・所属・その試合の成績・節目（`今季23号`） |
| `players[].hit` `pit` | 生スタッツ（主役選出用。文字列を正規表現で読まない） |
| `players[].seasonHit` `seasonPit` `warHit` `warPit` `rank` | 今季の到達点（SEASON帯・今季行） |
| `players[].games[]` | 所属チームのその日の結果。`game`（ja/en/score/decisions）と `opponent` `win` `extra` |

**出場0人なら何も作らない**（オールスター休みなど）。

🚨 この取得（statsapi）が失敗・空になったら、**推測で選手や成績を書かず即中止**する。

## Step 2 — カードを作る

```sh
node scripts/jp-daily-card.mjs 2026-07-29 --out public/media/jp-daily-2026-07-30.jpg
# → 縦カード（1080×1350）と 16:9版（-og.jpg・1200×578）の2枚が出る。両方コミットする
```

- 主役の選出・配色・レイアウトはスクリプトが全部やる（人が触らない）。主役は**数字だけ**で決まる。
- ファイル名は **JST日付**。`_local` はクラウドで永続化されないので出力先は `public/media/`。
- **素材（顔写真・ロゴ）は `public/media/card-art/` のローカルキャッシュを CDN より先に読む**。
  クラウド無人実行の環境は MLB の CDN（`img.mlbstatic.com` / `www.mlbstatic.com`）への egress を
  組織ポリシーで 403 拒否することがあり、2026-08-01・08-02 はそれで2日連続シリーズが止まった。
  キャッシュがあれば CDN 不通でも同じ絵が出る（取れた素材は自動でキャッシュに書き足される）。
- 🚨 **終了コード3＝素材が取れていない**＝CDN に届かず、キャッシュにも無い（新加入・初登場の選手など）。
  顔もロゴも無い抜け殻のカードができる（2026-07-31 No.128 で実際に公開してしまった）。
  **その画像はコミットしない**。直し方は**通常ネットワークの端末で `node scripts/warm-card-art.mjs`**
  （`src/lib/players.ts` の全選手＋30球団ぶんを取得してコミットする。`--force` で取り直し、
  引数に MLB選手ID を足せばカタログ外の選手も足せる）。それでも駄目なら**カードを諦めて記事も出さない**
  （素材抜きで押し切るのは `--allow-no-art` を明示した時だけ）。出力を目で見ないクラウド実行では、
  この終了コードが唯一の検知手段。
- カードのフッターにはドメイン `matome-mlb-kaigai.jp` が焼き込み済み＝転載されるたびに宣伝になる。

**カードの主役（標準出力1行目）＝記事の「②きょうの主役」**。ここを揃えないと、
X で見たカードと記事の顔が違って読者が迷子になる。

**16:9版（-og.jpg）は必ず記事の `media` に使う**。縦カードをそのまま OG にすると X・Discover・
記事ヒーローが中央だけを切り抜き、題字も主役も消える。縦カードは「⑤きょうの1枚」に置く。

## Step 3 — 動画を同定する（主役の試合＋ざわつきの試合）

```sh
node scripts/fetch-mlb-stats.mjs games 2026-07-29 --json   # searchQuery / titleDateName を得る
node scripts/fetch-youtube.mjs search "<searchQuery>" 5 --channel UCoLrcjPV5PbUrUyXq5mjc_A
```

- 採用は **channel が `MLB` かつ title に `(July 29)` がそのまま入っている**動画だけ。連戦は日付一致でしか確定しない。
- 主役の動画が無ければ**主役を2番手にずらす**（動画がある選手を主役にする）。カードは作り直す。
- 誰の動画も無ければ**記事は作らずカードだけ**出す（Slack にその旨を書く）。
- ④ざわつきが主役と別の試合なら、その試合の動画も同定して `buzz[n].media` に付ける。
- ④の2件目（日本人が絡まない試合）を書く日は、その試合の動画も同定する＝1日で最大3本。
- 二重作成ガード: `grep -rl "<videoId>" data/threads/` がヒットしたらその動画は使わない。

## Step 4 — コメントを取る

```sh
node scripts/fetch-youtube.mjs comments "<動画URL>" 200
```

日本人が出た試合の**上位2〜3試合ぶん**取る（主役・ざわつき・短評の引用の材料）。
生の取得 JSON は**コミットしない**（YouTube API 規約）。記事に残すのは抜粋だけ。

🚨 **コメントは1文字も創作しない**。`bodyEn`＝取得した `text` そのまま（改行だけ空白に詰める）、
`score`＝`likeCount` の実測値。保存前に取得 JSON と機械照合して全件一致を確認する（Step 6）。

## Step 5 — 記事を組む（`Thread.daily`）

`data/threads/mlb/{YYYY-MM-DD}-jp-daily.json`（日付は **JST**）。

### タイトル

```
{M/D} {主役の出来事}・{2人目}〔・{3人目}〕｜きょうのMLB日本人選手
```

末尾の `｜きょうのMLB日本人選手` は**固定**（シリーズ識別）。「MLB」を入れているのは、
タイトル単体で見たとき何の競技の日本人選手か分からないため（2026-07-31 変更）。

- 先頭の `{M/D}` は **JST＝記事 id と同じ日付**。ET の試合日（id の前日）を書かない
  （2026-07-31 No.128 で「7/30」と書いて公開＝カードの見出しだけ 7/31 でズレた）。
  データ源 `jpday` の `date` は **ET** なのでそのまま貼らない。
- **②③に出す順と同じ順**で選手を並べる（タイトル＝目次）。
- 選手名を先頭10字以内／全角32〜35字／「成績まとめ」「海外の反応」の語は使わない
  （「海外の反応」はサイト共通サフィックスが付く。書くと二重になる）。
- 誰も打たなかった日は `日本人◯人が出場` のように人数で受ける。
- **大谷が出場した日は、主役でなくてもタイトルの2〜3枠に必ず入れる**（例:「・大谷2安打」）。
  大谷は日本の Discover 最強エンティティ＝掲載判定に効く。

### コーナー構成（`daily` オブジェクト）

| コーナー | キー | 中身・分量 |
| --- | --- | --- |
| ① きょうの3行 | `threeLines` | 忙しい人はここで帰ってOKの要約。**必ず3行** |
| ② きょうの主役 | `hero` | **1人だけ**深く。`blocks`＝地の文と引用の交互で地の文700字前後＋引用10〜15件 |
| ③ 残り全員ひと言ずつ<br>（表示見出し=「そのほか日本人の活躍まとめ」） | `shorts` | 主役以外**全員**。1人3〜4行の短評＋あれば現地の一言（`quotes` 0〜2件） |
| ④ きょうの現地ざわつき | `buzz`（**配列・1〜2件**） | 1件目＝その日コメント欄がいちばん騒いだ話題（日本人と無関係でも可）。引用5〜8件。<br>2件目＝**日本人が誰も出ていない試合**を1つ（下の「2件目の枠」）。引用4〜6件 |
| ⑤ きょうの1枚 | `cardUrl` / `cardNo` | 縦カード。描画側が共有ボタン・転載OK表記・X導線を付ける |
| ⑥ あすの日本人 | `tomorrow` | 明日の先発予定・注目カード（**毎日読む理由**）。2〜3行 |

⚠️ **①〜⑥は編集側の内部ラベル＝読者には見えない**。本文に「詳しくは③で」「④に続く」「（④）」の
ような**番号での相互参照を書かない**（読者はその番号がどのコーナーか分からない）。後ろのコーナーに
振りたいときは番号でなく中身で言う（例:「この話はホワイトソックスのところで」）か、単に書かない。

### ④の2件目の枠 — 日本人が絡まない試合を1つ拾う（2026-08-07 新設）

チームLPの試合タイムラインは全試合を並べるが、**現地の声が出せるのは記事があるか、この日次記事が
触れた試合だけ**。日本人が出ていない試合はまとめ記事を作らないので、**この枠が唯一のコメント源**になる。
1日1試合ずつ拾うだけで、30球団のLPが少しずつ埋まっていく（実測: 声のカバー率は導入時 56%）。

1. `node scripts/team-note-candidates.mjs`（Step 6b と同じ）で**その日動いたチーム**を見る。
   連勝連敗・スイープ・首位攻防のどれかが乗っている試合を選ぶ。ここに日本人の出た試合しか無い日は
   **2件目を書かない**（無理に埋めない）。
2. その試合の MLB 公式ハイライトを Step 3 と同じ手順で同定する（`(August 5)` の日付一致が必須）。
3. コメントを取り、Step 4 と同じ規約で引用する（**1文字も創作しない・score は likeCount 実測**）。
4. **`result` を必ず書く**（`{自軍} {自軍得点}-{相手得点} {相手} ○/●` ＝ `DailyShort.result` と同じ書式）。
   これがチームLPのタイムラインとの紐づけキー。書き忘れると記事には出るが LP には出ない。
   自軍＝その話題の主役にしたチーム。地の文は R13（語り形式）＝**裏の取れた事実だけ**で、
   選手の状態や評価はコメントの証言として出す（地の文で断定しない）。
5. `tags` にその2球団を足す。

### ②④の本文ブロック（`DailyBlock`）

```jsonc
{ "type": "p",     "text": "地の文1段落" }
{ "type": "quote", "comment": { "author": "@…", "score": 78, "bodyEn": "…", "bodyJa": "…" } }
{ "type": "chips", "comments": [ /* 短い一言を3〜4個まとめて畳み掛ける（5chまとめのテンポ） */ ] }
```

**書き方の正は matome R13（語り形式）**＝地の文が語り・コメントは証言・裏取り事実のみ・対立軸・
正直さ・オチは最後の地の文。ここでは繰り返さない。jp-daily 固有の追加だけ:

- 対立軸の例: 泣いてる少年の中継倫理／大谷の敬遠論争（実際に割れている論点だけ拾う）。
- 言及が無い選手を正直に書くのは③短評でも同じ（「現地コメントに言及は見当たらなかった」）。

### ⑥ あすの日本人

```sh
curl -s "https://statsapi.mlb.com/api/v1/schedule?sportId=1&date=<ETの翌日>&hydrate=probablePitcher"
```

日本人の**先発予定**（probablePitcher）と、出場中の選手のチームの試合予定（日本時間の開始時刻つき）を
2〜3行に。**probables の実測のみ**＝取れなければコーナーごと省略。時刻は JST に変換して書く。

### JSON の書き方（このシリーズ固有）

```jsonc
{
  "id": "2026-07-30-jp-daily",
  "sport": "mlb", "format": "youtube", "subreddit": "YouTube",
  "sourceUrl": "<主役の公式ハイライトURL>",
  "title": { "ja": "7/30 村上23号・岡本3安打・大谷2安打｜きょうのMLB日本人選手", "en": "..." },
  "summaryJa": "…メタ説明用のリード（画面には出ない＝①が代わり）…",
  "totalComments": 647,            // 使った動画の総コメント数の合計（実測）
  "media": { "kind": "image", "url": "/media/jp-daily-2026-07-30-og.jpg", "width": 1200, "height": 578 },  // ← 16:9版・寸法必須（JSON-LD/Discoverの1200px宣言）
  "editorPick": 1,                 // その日の一面に固定（前日の jp-daily からは外す＝一面はきょうの1本だけ）
  "tags": ["村上宗隆", "…出場者全員…", "…主役/ざわつきの球団…", "海外の反応"],
  "comments": [],                  // ← 空。コメントは daily の blocks / quotes が持つ
  "daily": {
    "threeLines": ["…", "…", "…"],
    "hero": {
      "player": "村上宗隆", "team": "ホワイトソックス", "note": "今季23号",
      "line": "4打数1安打 1本塁打 1打点 1四球",
      "result": "ホワイトソックス 6-5 ヤンキース ○（延長10回）",   // 自軍を先に・○/●・延長はカッコで
      "season": "打率.240 23本 49打点 OPS.927（本塁打MLB13位）",
      "media": { "kind": "video", "url": "…", "thumbUrl": "…maxresdefault.jpg",
                 "credit": "MLB（YouTube公式ハイライト）", "publishedAt": "…", "videoTitle": "…" },
      "blocks": [ /* p / quote / chips */ ]
    },
    "shorts": [
      { "player": "岡本和真", "team": "ブルージェイズ", "result": "ブルージェイズ 5-2 ナショナルズ ○",
        "line": "5打数3安打 1二塁打 2打点", "season": "打率.231 24本 68打点 OPS.761",
        "text": "…編集部の短評2〜3行…", "quotes": [ /* 0〜2件 */ ] }
    ],
    "buzz": { "title": "「なぜ大谷と勝負しない」——歩かせた先の敬遠論争",
              "media": { /* その試合の動画 */ }, "blocks": [ /* p / quote / chips */ ] },
    "cardUrl": "/media/jp-daily-2026-07-30.jpg",
    "cardNo": 127,                 // jpday の day
    "tomorrow": ["…", "…"]
  }
}
```

- `stats` は付けない（成績は hero/shorts の `line`・`season` が持つ。StatBox と二重になる）。
- **`editorPick: 1` を付け、前日の `-jp-daily.json` から `editorPick` を外す**（TOPの一面＝常に最新号）。
- 恒久ハブ **/daily**（最新号＋コレクション）は `daily` を持つ記事から自動生成＝ハブ側の作業は無い。
- `series` は付けない（「海外ファンと見る」とは別シリーズ）。
- `thumbUrl` は `maxresdefault` が **HEAD で 200 のときだけ**（404 ならキーごと省略）。
- `tags` は**その日出場した選手だけ**＋主役/ざわつきの球団＋「海外の反応」。

## Step 6 — 保存前チェック

matome の Step4b に加えて、このシリーズ固有:

- [ ] **コメントを取得 JSON と機械照合した**（author＋原文一致・score＝likeCount）。1件でも合わなければ
      直すか落とす。過去に捏造21件の事故がある（`fabricated-comments-incident`）
- [ ] カードの主役と「②きょうの主役」が**同じ人**か／`cardNo` ＝ jpday の `day` か
- [ ] **地の文の事実がすべて裏取りできるか**（API の数値 or コメントの証言。イニング・場面を創作していないか）
- [ ] ②④の引用がそれぞれ**その試合の動画のコメントだけ**か（混線禁止）
- [ ] ④の**2件目（日本人が絡まない試合）を書いたか**。書いたなら `result` が入っているか
      ＝これが無いとチームLPのタイムラインに現地の声が出ない（候補が無い日はスキップでよい）
- [ ] `Thread.comments` が空配列／`stats` 無し／`media` が **16:9 の `-og.jpg`（width/height 付き）** か
- [ ] `editorPick:1` を付けたか／**前日の jp-daily から外した**か
- [ ] ③に主役以外の出場者が**全員**いるか。言及ゼロの選手を捏造引用で埋めていないか
- [ ] コメント合計 25件以上／`threeLines` が3行か
- [ ] 本文・`threeLines` に**①〜⑥の番号での相互参照が無い**か（「詳しくは③で」「（④）」等は読者に伝わらない）
- [ ] ⑥が probables の実測か（推測の先発予定を書かない）
- [ ] タイトル: 選手名が先頭10字以内・「海外の反応」「成績まとめ」を書いていない
- [ ] タイトル・`summaryJa` の先頭 `{M/D}` が **JST（=記事 id の日付・カードの見出しと一致）** か
- [ ] `npm run build:gate` が通るか（通常の build はクラウドで EMFILE で落ちる）
- [ ] **Step 6a（観測日誌の追記）を回して `node scripts/journal-gaps.mjs` が 0件になったか**。
      ここを飛ばすと選手タグLPの日誌だけが止まる（記事は出ているのにLPが死んで見える）
- [ ] **Step 6b（チームLPの中の人メモ）を回したか**。候補が出た日に書き漏らすと、メモが増えない
- [ ] **Step 6c（声レイヤー）を回して未訳を0にしたか**。ここを飛ばすとチームLPの試合の大半が
      結果表だけになる（記事が届くのは1日15試合中の数試合だけ）

## Step 6a — 観測日誌に追記する（毎日・必須）

選手タグLP（`/tag/{選手名}`）のシーズン観測日誌に、この日出場した選手ぶんのエントリを積む。
ルールの正は **matome 手順5c**（型・引用の規律・`editorJa` / `nextJa` を書かない規約）。ここは
「日次記事のあとに必ず回す」という**段取りだけ**を持つ。

なぜ独立の Step にしたか: 5c は matome 側の手順なので、日次記事を書く流れでは踏まれないことがあり、
**2026-08-13 の点検で全11人が2〜13日ぶん止まっていた**（22試合が未収録。鈴木誠也の20号、
山本由伸の7連敗ストップという山場まで抜けていた）。6b・6c と同じで、機械が候補を印字して
はじめて日課になる。

手順:

1. `node scripts/journal-gaps.mjs` を実行する。**日誌の最終エントリより後の jp-daily に出ている
   選手と試合**が印字される（0件なら何もしなくてよい）。
2. 印字された1件ごとに、`data/player-journal/{slug}.json` の `entries` へ matome 5c の型で追記する。
   `quotes` は**その日の記事JSONからの逐語コピーのみ**（1〜2件・その選手に言及している声を優先）。
   言及ゼロの日は `quotes: []` のまま出場の事実だけ残す＝タイムラインを切らさない。
3. `node scripts/check-journal-quotes.mjs` で逐語照合を通す（不一致のまま保存しない）。
4. `node scripts/journal-gaps.mjs` をもう一度回して 0件を確認する。

⚠️ `editorJa`（山場の観測メモ）・`peak`・`chapterJa`・`nextJa` は**クラウドでは書かない**
（matome 5c と同じ規約＝地の文と編集判断は人の編集セッション専用）。
⚠️ 日誌が無い選手は対象外。**新しく日誌を立てるのも編集セッションの仕事**で、ここではやらない。

## Step 6b — チームLPの「中の人メモ」を書き足す（1日1〜2件）

チームLP（`/tag/{チーム名}`）の試合タイムラインに、節目の試合だけ中の人の一言を挟む
（`data/team-notes.json` が正・型は `src/lib/teamNotes.ts`）。**日次で少しずつ増やす**のが前提で、
全球団を一度に埋めない。日本人が絡まないチームにも中の人の声が乗る＝LPが結果表で終わらなくなる。

手順:

1. `node scripts/team-note-candidates.mjs` を実行する。その日の**動きのあったチームと、書いてよい事実**が
   印字される（連勝連敗3以上・スイープ・地区首位・1点差・大差で機械的に選び、**その試合日に既にメモが
   あるチームは自動で除外**される）。候補なしの日は**書かない**＝無理に埋めない。
2. 上位1〜2件だけ書く。**印字された数値だけを言い換える**（思い出しで書かない＝ここが捏造の入口）。
   選手の調子・故障・移籍・過去シーズンなど、印字されていないことは一切書かない。
3. 声は `x-post` スキル（中の人・寝不足MLBオタク・一人称「俺」）が正典。脱AIルールをそのまま適用:
   - カギカッコ「」・引用符・半角スペースを使わない
   - 感想を整えない（○ さすがに顔が上がらない ／ ✕ 厳しい試合内容だった）
   - 締めは自分のリアクションの実況でなく、余韻・情・軽い問い
   - 2〜3文。スコアは行に出ているので**スコアの読み上げで終わらせない**
4. `data/team-notes.json` の該当 slug（`src/lib/teams.ts` の `slug`）に `{ "date", "noteJa" }` を追記。
   slug が無ければ新しいキーを作る。`date` は**試合日（JST）＝候補の date をそのまま**。

⚠️ ここで書くのは**チームの状況**についての一言だけ。選手の評価の推移は観測日誌（matome 5c）の担当で、
そちらの `editorJa` はクラウドで書かない規約のまま＝混ぜない。

## Step 6c — 声レイヤーを回す（毎日・必須）

チームLPのタイムラインは**全試合**が並ぶ。記事が届くのはそのうち数試合なので、残りの試合には
`data/game-voices.json`（1試合1件の現地の声）が声を出す。これを毎日回さないとカバー率が落ちる
（2026-08-07 の実測: 記事だけだと30〜40%、声レイヤー込みで97%）。

```bash
node scripts/fetch-game-voices.mjs              # 既定 = team-games.json の最新日
```

スクリプトが**原文・著者・票数・動画IDを取得結果からそのまま書き出す**（人も AI も触らない＝
ここで捏造は起きない）。`ja` は空で出てくるので、**空のものだけを訳して埋める**。

1. 実行して `✓` の行数と「未訳 N件」を確認する。記事が既に声を持つ試合は自動でスキップされる。
2. `data/game-voices.json` の `ja` が空のエントリを訳す。**`en` / `author` / `score` / `v` は絶対に触らない**。
3. 訳は1行のキャプション。原文の温度（皮肉・悪態・喜び）を落とさない。「ニキ」表現は禁止（CLAUDE.md §4.4）。
4. `ja` が空のまま残っても**サイトには出ない**（`src/lib/gameVoices.ts` の安全弁）＝未訳の英文が公開される事故は起きない。

編集判断で落としてよいもの（拾ってしまったら、そのエントリを消してもう一度スクリプトを回す。
同じものが返ってきたら `scripts/fetch-game-voices.mjs` の `SPAM` に足す）:

- 賭けサイトのステマ（票数が不自然に高く上位に来る。初回取得で25%混入した）
- 試合ではなく**動画そのもの**への感想（サムネ・音声・編集・広告）
- 個人への属性を絡めた中傷
- 意味の取れない略語だけの行（推測で訳さない）

⚠️ 1試合1件を超えて集めない（コメントDBにしない）。窓（直近30日）の外に出たエントリはスクリプトが
自動で落とす＝保存期間がタイムラインの窓と一致する。

## Step 7 — X に配る

  「{M/D}のきょうの日本人選手。」＋俺ボイスでその日いちばん言いたいこと＋末尾に `No.127`。
